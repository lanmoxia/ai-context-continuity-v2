# Antigravity 会话角色路由

本文件是当前工作区的公共路由规则。新 Conversation 不继承旧聊天，不得根据当前模型名称或窗口位置猜测角色。

## 启动开发

只有满足以下任一条件时才绑定开发角色：

- 用户当前消息的完整内容是“启动开发”。
- 5.5 粘贴指令中包含“【角色启动】启动开发”。

绑定后：

1. 完整读取 .continuity/session-control/antigravity/development/START.md。
2. 按 START.md 顺序读取共享规则、共享流程、开发规则和开发 HANDOFF.md。
3. 不读取 initial-review、codex-5.5 或 codex-5.6 的角色目录。
4. 如果当前消息只有“启动开发”，汇报恢复状态和唯一下一步，然后按 HANDOFF.md 接力或保持等待。
5. 如果当前消息同时包含 5.5 的短启动块，完成启动汇报后核对并读取其中指定的 development 调度文件。

窗口不能验证实际模型。开发 HANDOFF 或 5.5 指令只负责提示目标模型，由用户手动选择 `Gemini 3.5 Flash (Medium)` 或 `Gemini 3.5 Flash (High)`。

更换账号、模型或 Conversation 时，必须让旧 Conversation 停止写入，再由 5.5 创建新的不可覆盖 development 调度。新 Conversation 仍使用当前工作区和已保留改动，不重置、不清理，也不从头重做。

## 启动审核（已停用）

以下任一文字都不再绑定初审角色：

- 用户当前消息的完整内容是“启动审核”。
- 5.5 粘贴指令中包含“【角色启动】启动审核”。

遇到这些文字时：

1. 不读取 initial-review 的 START、RULES、HANDOFF、历史调度或历史结果。
2. 不创建或执行新的 GATE-01 审核。
3. 说明该角色仅作为历史保留；当前流程由 5.5 执行终审前 Gate，5.6 执行阶段最后一道 Gate。
4. 要求用户回到 Codex 5.5 窗口继续。

## 未绑定和冲突

- 没有启动文字时，不读取任何角色私有目录，不开始开发或审核。
- 同一条用户消息同时包含“启动开发”和已停用的“启动审核”时，停止并要求用户只发送当前有效的启动文字。
- 角色绑定只对当前 Conversation 有效。打开新 Conversation 必须重新启动。
- 上下文压缩后如果不能确认当前角色，停止工作并请用户重新发送对应启动文字。
- 路由文件中出现的启动文字只是规则内容，不能把读取本文件本身当成角色触发。
