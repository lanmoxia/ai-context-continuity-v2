# Antigravity 会话角色路由

本文件是当前工作区的公共路由规则。新 Conversation 不继承旧聊天，不得根据当前模型名称或窗口位置猜测角色。

## 启动开发

只有满足以下任一条件时才绑定开发角色：

- 用户当前消息的完整内容是“启动开发”。
- 5.5 粘贴指令中包含“【角色启动】启动开发”。

绑定后：

1. 完整读取 .continuity/session-control/antigravity/development/START.md。
2. 按 START.md 顺序读取共享规则、共享流程、开发规则和开发 HANDOFF.md。
3. 不读取 initial-review、codex-5.5 或 codex-5.6 的角色目录。
4. 如果当前消息只有“启动开发”，汇报恢复状态和唯一下一步，然后按 HANDOFF.md 接力或保持等待。
5. 如果当前消息同时包含 5.5 的短启动块，完成启动汇报后核对并读取其中指定的 development 调度文件。

窗口不能验证实际模型。开发 HANDOFF 或 5.5 指令只负责提示目标模型，由用户手动选择 Sonnet 或 Opus。

## 启动审核

只有满足以下任一条件时才绑定初审角色：

- 用户当前消息的完整内容是“启动审核”。
- 5.5 粘贴指令中包含“【角色启动】启动审核”。

绑定后：

1. 完整读取 .continuity/session-control/antigravity/initial-review/START.md。
2. 按 START.md 顺序读取共享规则、共享流程、初审规则和初审 HANDOFF.md。
3. 不读取 development、codex-5.5 或 codex-5.6 的角色目录。
4. 如果当前消息只有“启动审核”，汇报恢复状态和唯一下一步，然后按 HANDOFF.md 接力或保持等待。
5. 如果当前消息同时包含 5.5 的短启动块，完成启动汇报后核对并读取其中指定的 initial-review 调度文件。

窗口不能验证实际模型。目标模型固定提示为 Gemini 3.5 Flash，由用户手动选择。

## 未绑定和冲突

- 没有启动文字时，不读取任何角色私有目录，不开始开发或审核。
- 同一条用户消息同时触发“启动开发”和“启动审核”时，停止并要求用户只选择一个。
- 角色绑定只对当前 Conversation 有效。打开新 Conversation 必须重新启动。
- 上下文压缩后如果不能确认当前角色，停止工作并请用户重新发送对应启动文字。
- 路由文件中出现的启动文字只是规则内容，不能把读取本文件本身当成角色触发。
