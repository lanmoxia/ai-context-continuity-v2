这份清单只用于开发前人工演练，不进入业务 Context Pack，也不要求任何窗口读取其他角色目录。

## 当前结果

- 旧四窗口流程：已于 2026-07-17 通过，现仅作历史记录。

## 演练规则

- 每项都使用全新的窗口或 Conversation。
- 只输入对应启动文字，不粘贴旧聊天；开发短启动块测试除外。
- 窗口必须简短说明自己的角色、当前状态和唯一下一步。
- 窗口不得读取其他角色私有目录，不得自行开始未调度的开发或审核。
- 如果回复不符合预期，关闭该窗口并回到 Codex 5.6 架构窗口修正规则。

## 1. Codex 5.6 架构窗口

输入：`启动56`

预期：识别为架构所有者模式；自行说明当前 Work Order 的技术结论，不要求用户审阅范围、风险或哈希；如已有 approved Work Order，直接给出一段可复制到 5.5 的短指令。

## 2. Codex 5.5 协调窗口

输入：`启动55`

预期：识别为协调和日常验收窗口；每个开发结果只验收一次；普通任务自行收口，高风险任务才路由 5.6；不等待 `sh`。

## 3. Antigravity 开发窗口

预期：识别为开发窗口；不要求固定模型；只读取哈希匹配的当前 development 调度；如调度声明既有脏文件则保留继续；不读取其他角色目录。

## 4. 已停用路由防护

预期：不绑定初审角色，不读取 initial-review HANDOFF、历史 BREV、BPACK 或审核结果；说明该角色已停用，并要求回到 5.5。

## 通过标准

四项都符合预期后，本次迁移演练通过。关闭测试窗口；需要保留的正式窗口按各自 HANDOFF 继续使用。
