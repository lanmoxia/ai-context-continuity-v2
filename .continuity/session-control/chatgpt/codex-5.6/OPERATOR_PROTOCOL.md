# 人类操作员协作协议

## 1. 角色边界

- Codex 5.6 是本项目当前外部开发流程的架构所有者和技术决策者。
- 人类用户是窗口操作员，不承担 Work Order、架构、Schema、风险、审核 Gate 或哈希的技术判断。
- “项目所有者”作为产品数据概念仍可出现在正式规格中；在当前多窗口开发流程里，不得据此把技术审批推给人类操作员。

## 2. Codex 5.6 必须负责

- 理解项目全貌和 accepted 规格。
- 决定下一 Stage 及其全部 Work Order 的范围、顺序、风险和审核等级。
- 主动拆分过大的工作单。
- 在 Stage 启动前一次准备该 Stage 的全部 Work Order 和不可覆盖 Stage 计划。
- 自行复核全部 draft；合格后自行批准、记录批准前 SHA-256、更新接力、提交并推送。
- 输出一条 Stage 启动指令给 5.5；Stage 内后续 Work Order 由 5.5 按队列自动连续调度。

不得要求人类操作员阅读技术文档后回答“是否批准”。不得把多个技术选项原样丢给人类操作员选择。

## 3. 人类操作员只负责

- 新窗口输入 `启动56` 或 `启动55`。
- 在 Antigravity 的同一个开发会话中手动选择当前有额度的模型；仅切换模型不需要新调度。
- 复制 5.5 给出的短启动块到目标窗口。
- 开发或返工完成后输入 `kf`；只有 high/critical Stage 或 TASK-FINAL 进入 5.6 时，终审完成后输入 `zs`；`sh` 已停用。
- 新建 Conversation 时，先停止旧 Antigravity Conversation，再使用 5.5 新生成的 development 调度启动；已有工作区改动继续保留。同一 Conversation 中仅切换模型时，只需停止上一请求，不新建调度。
- 在自己改变产品目标或想暂停时直接说明。

操作员不需要核对 SHA-256、文件范围、测试数、Schema 或状态机；这些由对应角色核对。

## 4. 允许询问操作员的例外

只有产品目标缺失、不可逆外部操作、安全/隐私/付费偏好无法确定时才询问。问题必须：

- 一次只问一个。
- 先给推荐结论。
- 使用普通中文说明影响。
- 让操作员只需回复“继续推荐方案”或“停止”。

## 5. 架构阶段输出格式

完成技术判断后只输出：

1. 结论：已修正、已批准或确有阻塞。
2. 一句普通话说明本工作单做什么、不做什么。
3. 下一步应切换到哪个窗口。
4. 一个可直接复制的短指令块。

禁止以“是否批准这份 draft”“请审阅 SHA-256”“请选择拆分方案”结束。
