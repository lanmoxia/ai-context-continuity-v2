# 调度指令文件

本目录保存 5.5 发给其他窗口的外部调度指令。它属于会话控制层，不是产品生成的 Context Pack、Review Pack 或核心状态，禁止进入业务 Context Pack。

## 目录与编号

```text
dispatches/
  development/       BDEV-0001-r1.md，给 Antigravity 开发会话执行或返工
  initial-review/    BREV-0001-r1.md，旧流程初审调度，只作历史保留
  pre-final-review/  旧流程终审前调度，只作历史保留
  final-review/      BFINAL-0001-r1.md，给 5.6 执行高风险 Stage 最终 Gate 或 TASK-FINAL
```

- 新的可执行步骤使用下一个编号，初始修订为 `r1`。
- 已生成文件只读、保留并进入 Git，不覆盖、不改名、不删除。
- 尚未执行的错误指令使用新修订，例如 `r2`；新文件写明 `supersedes`，旧文件保持原样。
- 当前有效文件只由 5.5 HANDOFF 的精确路径与 SHA-256 指针确定，不使用 `latest.md`。
- Task 完成后可以整体移入会话控制归档，但不得永久删除。

## 文件最小内容

每份调度文件只保存当前一步需要的路由信息：

1. 类型、ID、修订、生成时间、生成者和目标角色。开发调度记录模型选择策略为“用户手动选择当前可用模型”，不绑定具体模型。
2. `supersedes`，没有则写 `none`。
3. Task、Stage、Work Order、分支和精确业务执行基线。
4. 开发时引用权威 Work Order JSON 路径与 SHA-256；审核时只引用精确 BPACK 路径、BPACK SHA-256 和结果路径。
5. 唯一目标、精确读取顺序、允许存在的预先修改、停止条件和完成回传。

允许路径、交付物、验收标准和 required checks 继续以 Work Order JSON 为唯一事实来源，不复制进调度文件。审核调度不得复制 BPACK 的文件清单、检查表或指纹，也不得把开发者 HANDOFF 作为审核输入。修复 Finding 时只列当前被 5.5 接受的 Finding ID、最小证据和来源结果文件哈希。

## 读取规则

- 聊天只携带短启动块：角色启动、调度文件路径和文件 SHA-256，不携带具体模型名。
- 目标窗口先完成角色启动，再核对并只读取短启动块指定的一个调度文件。
- 禁止列出或扫描整个 `dispatches/`，禁止读取历史修订猜测当前任务。
- 调度文件只负责路由到权威事实，不能覆盖 Work Order、Pack 或角色规则。
- Antigravity 同一开发会话内手动切换模型不需要新调度；新开开发会话时必须由 5.5 创建续作调度。

## Git 保存规则

- 调度文件与 5.5 HANDOFF 必须在发给目标窗口前作为纯会话控制提交进入当前 Task 分支并推送远端。
- 文件中的“业务执行基线”是本轮业务 diff 的起点，不因为保存调度文件而变化。
- 保存调度文件的后续提交只能包含该调度文件和 5.5 HANDOFF，不能夹带业务代码。
- 目标窗口验证当前分支包含业务执行基线，并确认从该基线到开始执行前只有已声明的会话控制变更；不得机械要求当前 HEAD 等于业务执行基线。
