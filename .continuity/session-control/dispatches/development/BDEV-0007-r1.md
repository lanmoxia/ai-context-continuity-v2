## 已确认 Findings

### BG03-F01 - high - 实体 ID 与引用字段未按实体类型精确约束

最小证据：共享 `stable_id` 只要求任意大写前缀；Context Pack 的 `stage_id`、`checkpoint_id`、`handoff_id`、`review_pack_id` 接受任意字符串或 null。5.6 探针确认 `task.id = STAGE-0001`、`stage.task_id = STAGE-0001`、Context 引用值 `anything` 均返回零错误。

修复要求：

- 为每类实体定义固定前缀 ID 及 nullable 变体，并应用到实体自身 ID、外键和 Context 引用。
- 补充错误但格式合法的跨类型前缀 fixture 或单元测试，逐字段证明会被拒绝。

### BG03-F02 - high - Review Pack Schema 缺少完整 Source Fingerprint 绑定与 scope 条件约束

最小证据：Review Pack 顶层没有完整 `source_fingerprint` 字段；`evidence_refs.source_fingerprint_sha256` 不是必填；`scope` 没有约束 `stage_id` 与 `stage_sha256`。5.6 探针把合法 Stage Pack 改为 `scope = task` 且保留非空 Stage 字段，仍返回零错误。

修复要求：

- 将完整 Source Fingerprint 设为 Review Pack 必填字段，并要求 evidence refs 携带 source fingerprint 哈希。
- 使用 Draft 2020-12 条件 schema 约束：`task` scope 的 Stage 字段必须为 null，`stage` scope 的 Stage 字段必须非 null。
- 补充 task/stage scope 的反例测试。

### BG03-F03 - medium - 项目相对路径合同未拒绝绝对路径和目录穿越

最小证据：`path_string` 只有 `minLength: 1`。5.6 探针确认 Stage `allowed_paths` 使用 `../outside.py` 和 `C:/outside.py` 仍返回零错误。

修复要求：

- 在 Schema 层拒绝绝对路径、盘符路径、UNC 路径，以及包含 `.` 或 `..` 路径段的路径。
- 保留真实规范化、符号链接和越界检查给后续 DEV-004；本轮只实现可由 Schema 判断的语法边界。
- 补充 Windows、POSIX 和 traversal 反例。

最小证据：`check_argv_entry.required` 只有 `id` 和 `argv`，虽然对象定义了 `cwd`、`timeout_seconds`、`allowed_exit_codes`。5.6 探针确认 Config 中只含 `id` 和 `argv` 的检查条目仍返回零错误。
