## 已确认 Finding

### F-GATE03-0003-01 - medium - 结构化错误顺序依赖输入对象的键插入顺序

最小证据：

- 位置：`src/continuity/schemas/registry.py:276`、`src/continuity/schemas/registry.py:287`、`src/continuity/schemas/registry.py:306`
- 关联测试：`tests/unit/test_schemas.py:282`、`tests/unit/test_schemas.py:345`
- `validate()` 先排序 jsonschema 错误，随后 `_check_rfc3339_strict()` 按 Python 字典插入顺序追加严格时间错误，但追加后未统一重排。
- 对两个键值完全相同、仅键插入顺序相反的 Task 对象，同时令 `created_at` 与 `updated_at` 为非法日历日期，返回顺序分别为 `[created_at, updated_at]` 和 `[updated_at, created_at]`。
- 现有稳定性测试只对同一对象连续调用两次，未覆盖等价对象键顺序变化；严格时间测试也未断言全局排序。

影响：

- WORK-0002 要求 Schema 失败返回稳定排序的结构化错误；`validate()` 的公开文档也承诺返回 stably sorted list。
- 当前实现让等价 JSON 值可能因解析或构造时的对象键顺序不同而产生不同错误列表，破坏稳定排序合同，并可能使调用方输出、快照和证据哈希不稳定。

修复要求：

- 在严格 RFC 3339 检查追加完成后，对合并后的结构化错误按稳定键统一排序。
- 新增一个回归测试：两个字段集合和值相同、键插入顺序相反的实例，同时包含至少两个严格时间错误，`validate()` 返回的错误列表顺序必须一致。
- 新增或扩展测试覆盖 jsonschema 错误与严格时间错误共存时的全局稳定排序。
- 保留现有 44 项测试覆盖，不删除已有 fixtures，不降低 `$ref` 安全边界、ID 前缀、Review Pack scope、检查项必填、路径边界或 `.venv` 检查证据要求。
- 修复后重新运行全部 required checks；UNIT 必须记录测试数量和 `0 skipped`。
- 重新运行 `git diff --check` 并记录退出码。
