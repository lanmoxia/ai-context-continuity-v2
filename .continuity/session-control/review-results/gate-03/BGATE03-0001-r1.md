### BG03-F01 - 实体 ID 与引用字段没有按实体类型精确约束

- Severity：high
- Location：`src/continuity/schemas/common.schema.json:12`；`src/continuity/schemas/context-pack.schema.json:14`
- Evidence：共享 `stable_id` 只要求任意大写前缀；Context Pack 的 `stage_id`、`checkpoint_id`、`handoff_id`、`review_pack_id` 甚至只要求任意字符串或 null。独立探针确认 `task.id = STAGE-0001`、`stage.task_id = STAGE-0001` 以及 Context 引用值 `anything` 均返回零错误。
- Impact：错误实体类型可以进入公共持久化合同，后续无法仅凭 Schema 区分 Task、Stage、Work Order、Checkpoint、Handoff、Pack 等引用，违反固定前缀和“引用字段精确约束”的验收要求。
- Recommendation：为每类实体定义固定前缀 ID 及 nullable 变体，并应用到所有实体自身 ID、外键和 Context 引用；补充错误但格式合法的跨类型前缀 fixture 与逐字段拒绝测试。

### BG03-F02 - Review Pack Schema 无法绑定完整 Source Fingerprint，且未约束 scope 对应字段

- Severity：high
- Location：`src/continuity/schemas/review-pack.schema.json:7`
- Evidence：Review Pack 顶层没有 `source_fingerprint` 字段，Evidence 引用中的 `source_fingerprint_sha256` 也不是必填；Schema 同时没有按 `scope` 约束 `stage_id` 与 `stage_sha256`。独立探针把合法 Stage Pack 的 `scope` 改为 `task` 后，保留非空 Stage 字段仍返回零错误。
- Impact：产品正式 Review Pack 无法用 Schema 表达与 Evidence 相同的完整源码指纹，也能持久化自相矛盾的 Task/Stage Pack 形状，破坏审核材料版本绑定与 freshness 可信度。
- Recommendation：把完整 Source Fingerprint 设为 Review Pack 必填字段；要求 Evidence 引用携带指纹哈希；用 Draft 2020-12 条件约束确保 task scope 的 Stage 字段为 null、stage scope 的 Stage 字段非 null，并补充两类 scope 的反例测试。
