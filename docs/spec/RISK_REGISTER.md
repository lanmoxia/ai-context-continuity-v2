# 风险清单

## 高风险

| 风险 | 后果 | 第一版控制办法 |
|---|---|---|
| 状态事实在多份文件重复 | 新窗口读到互相矛盾的进度 | JSON 单一事实来源，Markdown 全部生成 |
| 把所有项目文档塞进上下文 | 临时讨论、未确认决定或其他任务污染当前工作 | 文档注册表默认拒绝，按 purpose 生成最小 Context Pack |
| 窗口突然中断且没有保存 | 最近工作无法恢复 | 小步 Checkpoint，并明确未保存区间不可恢复 |
| 审核后代码又变化 | 旧审核被错误用于新代码 | Pack ID、manifest 哈希和自动 stale |
| 两个开发窗口同时改代码 | 变更归属和接力失真 | 一个 active 主任务、一个 Writer Lease、Checkpoint 续租 |
| 原有脏工作区混入本任务 | 审核范围错误 | 启动时记录基线指纹，无法区分时阻止正式审核 |
| 检查结果来自旧版源码 | 未验证的代码被当成已验证 | Evidence 绑定 Source Fingerprint，变化后自动 stale |
| 密钥进入 diff 或审核包 | 凭据泄露给模型或日志 | 敏感信息扫描、脱敏报告、默认阻止打包 |
| 路径或符号链接越界 | 读取或复制项目外文件 | 使用真实路径校验，所有收集动作限制在项目根目录 |
| 自动 commit/push 提交无关修改 | 未完成或不属于当前任务的代码进入远端 | 只允许 Work Order 路径和可恢复状态；发现其他修改即停止 |
| 两台电脑形成不同 Git 历史 | 自动同步覆盖或合并错误版本 | resume 只允许 fast-forward，禁止自动 rebase、merge 和 force push |
| Task Final Review 后代码变化 | 未审核代码进入主分支 | Final Pack 和 Merge Plan 新鲜度检查，变化后重新审核和确认 |

## 中风险

| 风险 | 后果 | 第一版控制办法 |
|---|---|---|
| 历史接力越来越长 | token 消耗重新失控 | 启动页只指向最新记录，历史按需读取，设置大小警告 |
| 外部执行者直接手改核心 JSON | 跳过校验造成损坏 | CLI 检测版本和 Schema；核心写入只经过状态仓库 |
| 审核过程中修改业务代码 | 审核输入与结论错位 | 审核使用冻结 Pack；任何源码变化使 Pack stale |
| 项目内容包含提示注入文字 | 普通文件被误当成高优先级指令 | Context manifest 明确事实边界，项目内容按数据处理 |
| 导入的检查结果被冒充为直接执行 | 证据可信度被夸大 | `captured` 与 `imported` 分级并写入 Review Pack |
| Schema 升级失败 | 已有项目不能继续读取 | 每个文件保存 `schema_version`，迁移先备份并支持 dry-run |
| 工具版本与项目数据版本不匹配 | 读取或写入结果不可预测 | 启动时检查兼容范围，不兼容时只读并提示升级 |
| 记录长期增长 | 项目体积和读取成本增加 | 完成任务后只移动归档，运行时默认不扫描归档 |
| 日志或遥测泄露项目内容 | 本地敏感数据离开预期边界 | 核心工具默认离线、无遥测，日志脱敏和轮转 |
| 全量恢复数据使 Git 体积增长 | clone、fetch 和历史操作变慢 | 单文件大小限制、合规归档、运行时目录排除，不静默遗漏数据 |
| 审核副本修改误入正式分支 | 审核职责和代码版本混乱 | 隔离 worktree/克隆，只导出 Suggested Patch，禁止自动合并 |
| squash 后过程提交难以寻找 | 追溯阶段开发历史困难 | 合并前在 Task 分支最终提交创建并 push 归档标签 |

## 无法完全由工具解决的边界

- 工具不能恢复从未写入文件的聊天内容。
- 工具不能阻止用户或外部客户端绕过 CLI 直接修改源码。
- 工具不能保证模型审核一定正确，只能保证审核材料、版本和结论对应关系可信。
- 工具不能在缺少 Git 基线时证明一份正式代码审核覆盖了哪一版代码。

产品输出必须如实显示这些边界，不能用“自动恢复”或“已审核”等模糊表述掩盖。
